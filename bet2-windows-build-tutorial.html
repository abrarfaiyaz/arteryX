FSL · Brain Extraction Tool · Native Windows Build

Compiling BET2 from source on Windows

A start-to-finish walkthrough for building FSL's Brain Extraction Tool as a native Windows executable — no WSL, no virtual machine — and placing it into the University of Rochester project.

toolchain MSYS2 · MinGW-w64 source liangfu/bet2 output bet2.exe runtime deps none

FSL is a Linux and macOS project — there is no officially supported native Windows build. The usual workaround is to run it inside WSL or a Linux VM. This guide takes the other route: it compiles a standalone fork of BET2 (which bundles all of its dependencies and uses CMake instead of FSL's build system) into a real Windows .exe that runs on its own.

The finished binary links against only KERNEL32.dll and msvcrt.dll — libraries present on every Windows machine — so it is fully portable. Copy it anywhere and it runs.

Destination: the compiled tool needs to end up at
C:\Program Files\University of Rochester\fslbet2
Why it doesn't build out of the box

Three fixes for a modern toolchain

The source predates current C++ compilers. Each problem below has a one-flag solution, and all three are already folded into the build command in Slice 03 — so you don't apply them by hand.

FIX 01

Old exception syntax

The code uses throw() dynamic exception specifications, which C++17 removed. Compiling against an older standard restores them.

-std=c++14
FIX 02

Missing <cstdint>

It uses int64_t without including the header. Linux pulled it in transitively; Windows toolchains don't, so we force-include it.

-include cstdint
FIX 03

Ancient CMake floor

The project declares cmake_minimum_required(2.8.7), which modern CMake refuses. A policy override accepts it.

-DCMAKE_POLICY_VERSION_MINIMUM=3.5
SLICE 01

Install MSYS2 and the compiler toolchain

MSYS2 provides the MinGW-w64 compiler that produces native Windows binaries. It is a separate program — its commands do not work in the ordinary Command Prompt.

Download the installer from msys2.org and run it (defaults are fine; it installs to C:\msys64). Then open the “MSYS2 MINGW64” shell from the Start menu — the blue one, not the Command Prompt and not the plain “MSYS2 MSYS” shell. You'll know you're in the right place when the prompt ends in $ rather than C:\Users\…>.

MSYS2 MINGW64 — update base system
$ pacman -Syu
If the update asks to close the terminal, close it, reopen MSYS2 MINGW64 from the Start menu, then continue with the install below.
install git, gcc, cmake, make
$ pacman -S --needed git \
    mingw-w64-x86_64-gcc \
    mingw-w64-x86_64-cmake \
    mingw-w64-x86_64-make
SLICE 02

Move the source to a clean working folder

Don't build inside C:\Program Files. It's write-protected, and the spaces in the path break MinGW's make. Instead, copy the source into your MSYS2 home directory — a short, writable, space-free location — and build there.

In the MSYS2 shell, Windows drives are addressed as /c/…, and any path with spaces goes in quotes:

copy source into ~/bet2build
$ cp -r "/c/Program Files/University of Rochester/fslbet2" ~/bet2build
$ cd ~/bet2build
Watch for a nested folder. If the source was unzipped from GitHub, the actual project may sit one level down (e.g. a bet2-master subfolder). The real source directory is wherever the top-level CMakeLists.txt lives — find it with the command below and cd into that folder before building.
locate the top-level CMakeLists.txt
$ find ~/bet2build -name CMakeLists.txt
# cd into the folder that contains the top-level result
SLICE 03

Configure with CMake — the three fixes applied

From inside the source folder, create a scratch build directory and run CMake. This single command carries all three compatibility flags plus static-linking options that bake the runtime into the executable, so it needs no MinGW DLLs alongside it.

configure the build
$ mkdir build && cd build
$ cmake -G "MinGW Makefiles" \
    -DCMAKE_POLICY_VERSION_MINIMUM=3.5 \
    -DCMAKE_CXX_FLAGS="-std=c++14 -fpermissive -w -include cstdint -include cstdlib -static -static-libgcc -static-libstdc++" \
    -DCMAKE_EXE_LINKER_FLAGS="-static -static-libgcc -static-libstdc++" \
    ..
The trailing .. matters — it points CMake at the source folder one level up. A “does not contain CMakeLists.txt” error almost always means you ran this from the wrong directory (see Slice 02's nested-folder note).
SLICE 04

Build the executable

Compile everything. CMake builds the bundled dependency libraries first — newmat, miscmaths, newimage, meshclass, and the rest — then links bet2.exe at the end.

compile (4 parallel jobs)
$ cmake --build . -j4
Success looks like [100%] Linking CXX executable …\bin\bet2.exe followed by [100%] Built target bet2. The finished binary lands in the bin folder beside your build directory.
SLICE 05

Verify the binary works

Before placing it, confirm it actually runs. Launch it with no arguments — a healthy build prints its version banner and full options list.

smoke test — print usage
$ ../bin/bet2.exe
BET (Brain Extraction Tool) v2.1 - FMRIB Analysis Group, Oxford
Usage: bet2 <input_fileroot> <output_fileroot> [options]

Then run a real end-to-end extraction on a NIfTI image to confirm it processes data correctly, not just that it launches:

real extraction
$ ../bin/bet2.exe input.nii.gz output_brain.nii.gz -f 0.5

Open output_brain.nii.gz in a viewer and confirm it looks like a cleanly skull-stripped brain.

SLICE 06

Place it into the University of Rochester project

Now copy the verified binary into its destination. Because C:\Program Files is protected, a normal shell copy is denied — that's expected. Use whichever of these is easiest:

Easiest — File Explorer. Open C:\msys64\home\<you>\bet2build\…\bin\, copy bet2.exe, paste it into the fslbet2 folder, and click Continue on the administrator prompt.

Or run the copy from an administrator MSYS2 shell (right-click “MSYS2 MINGW64” → Run as administrator):

place binary (admin shell)
$ cp ../bin/bet2.exe "/c/Program Files/University of Rochester/fslbet2/"
If the project invokes the tool as bet rather than bet2, drop a copy named bet.exe in the same folder — for standard extraction they're interchangeable. The advanced surface options (-A / -A2) additionally require betsurf.exe, which builds from the same source with the same flags.

What you built

A native Windows build of FSL's Brain Extraction Tool, compiled from source on your own machine and wired into the project — no WSL or VM at runtime.

The recipe
Three flags make old code compile on a modern toolchain: -std=c++14, -include cstdint, and -DCMAKE_POLICY_VERSION_MINIMUM=3.5.
Portable output
Static linking leaves only KERNEL32.dll and msvcrt.dll as dependencies — no runtime to ship.
Reproducible
The Slice 03 CMake command is your build recipe. Save it to rebuild or hand off to a colleague.
